# 商品级别自动发货配置功能

## 功能概述

本次更新添加了商品级别的自动发货配置功能，允许为每个商品单独配置发货卡券，实现更精细化的自动发货控制。

## 功能特点

1. **商品级别配置**：可以为每个商品单独配置发货卡券
2. **优先级机制**：商品级别配置优先级高于全局发货规则
3. **灵活切换**：可以随时启用或禁用商品级别配置
4. **多规格支持**：支持多规格卡券的自动匹配
5. **向后兼容**：不影响现有发货规则功能

## 使用方法

### 1. 配置发货卡券

1. 进入"商品管理"页面
2. 找到需要配置的商品
3. 点击"发货配置"列的"配置"按钮
4. 在弹窗中选择要使用的卡券（只显示已启用的卡券）
5. 点击"保存"完成配置

### 2. 查看配置状态

- **已配置**：商品已配置发货卡券，显示蓝色标签
- **配置**：商品未配置，显示灰色标签

### 3. 取消配置

1. 点击商品的"配置"按钮
2. 在下拉框中选择"不配置（使用发货规则）"
3. 点击"保存"

## 工作原理

### 自动发货流程

1. **检查商品配置**：优先检查商品是否配置了发货卡券
2. **使用商品配置**：如果配置了卡券且可用，直接使用该卡券发货
3. **回退到规则**：如果未配置或配置不可用，使用原有的发货规则匹配
4. **执行发货**：根据卡券类型（API/文本/批量/图片）执行相应的发货操作

### 优先级说明

```
商品级别发货配置 > 发货规则匹配
```

- 如果商品配置了卡券，将直接使用该卡券，不再进行发货规则匹配
- 如果商品未配置或配置的卡券不可用，则使用发货规则匹配

## 技术实现

### 数据库变更

在 `item_info` 表添加了 `delivery_card_id` 字段：

```sql
ALTER TABLE item_info ADD COLUMN delivery_card_id INTEGER;
```

### 新增API接口

1. **获取商品发货配置**
   - 路径：`GET /items/{cookie_id}/{item_id}/delivery-config`
   - 返回：`{ success: true, data: { card_id: number | null } }`

2. **更新商品发货配置**
   - 路径：`PUT /items/{cookie_id}/{item_id}/delivery-config`
   - 参数：`{ card_id: number | null }`
   - 返回：`{ success: true, message: "商品发货配置已更新" }`

### 前端变更

1. 在商品管理表格添加"发货配置"列
2. 实现发货配置弹窗，支持选择卡券
3. 显示配置状态（已配置/配置）

### 后端变更

1. 在 `db_manager.py` 添加数据库操作方法
2. 在 `reply_server.py` 添加API接口
3. 在 `XianyuAutoAsync.py` 修改自动发货逻辑

## 使用场景

### 场景1：不同商品使用不同卡券

- 商品A配置卡券1（API类型）
- 商品B配置卡券2（批量数据类型）
- 商品C不配置（使用发货规则）

### 场景2：多规格商品精确控制

- 商品有多个规格（如：颜色、尺寸）
- 为每个规格配置不同的多规格卡券
- 系统自动根据订单规格匹配对应卡券

### 场景3：临时调整发货策略

- 某商品临时需要使用特定卡券
- 快速配置商品级别卡券
- 无需修改全局发货规则

## 注意事项

1. **卡券状态**：只能选择已启用的卡券
2. **多规格匹配**：如果配置的是多规格卡券，需要确保订单规格与卡券规格匹配
3. **配置优先级**：商品配置优先级最高，会覆盖发货规则
4. **数据库迁移**：首次启动时会自动添加 `delivery_card_id` 字段
